# Техническое задание для OpenCode

## Проект

Создать адаптивное веб-приложение «Daily Task Tracker» — простой личный трекер ежедневных задач и прогресса.

Источник задания: https://www.upwork.com/freelance-jobs/apply/Simple-Daily-Task-List-Dashboard_~022100134927726860353/

## Цель проекта

Пользователь должен иметь возможность:

- добавлять задачи;
- видеть список текущих задач;
- отмечать выполненные задачи;
- удалять и редактировать задачи;
- видеть понятную сводку за день:
  - сколько задач всего;
  - сколько выполнено;
  - сколько осталось;
  - процент выполнения.

Приложение должно быть простым, понятным и удобным для использования с компьютера и телефона.

## Формат MVP

Сделать одностраничное веб-приложение без регистрации и серверной части.

Данные хранить в браузере пользователя через `localStorage`, чтобы задачи не исчезали после обновления страницы или повторного открытия приложения.

Не добавлять на первом этапе:

- авторизацию;
- серверную базу данных;
- командную работу;
- уведомления;
- интеграции;
- календарь;
- сложные роли пользователей.

## Основной пользователь

Один пользователь, который планирует свои задачи на текущий день и отмечает их выполнение.

## Структура страницы

### 1. Шапка

В шапке разместить:

- название приложения: Daily Task Tracker;
- текущую дату;
- короткую фразу: «Планируйте день и отслеживайте свой прогресс».

### 2. Блок статистики

В верхней части страницы показать четыре компактные карточки:

- Всего задач;
- Выполнено;
- Осталось;
- Прогресс.

В карточке «Прогресс» показывать процент выполнения и визуальный progress bar.

Пример:

- Всего задач — 8;
- Выполнено — 5;
- Осталось — 3;
- Прогресс — 62%.

### 3. Форма добавления задачи

Форма должна содержать:

- поле «Название задачи»;
- необязательное поле «Описание»;
- кнопку «Добавить задачу».

Правила:

- название задачи обязательно;
- нельзя добавлять пустую задачу;
- после добавления форма очищается;
- новая задача появляется в списке сразу.

### 4. Список задач

Каждая задача должна отображаться отдельной карточкой.

В карточке показать:

- чекбокс выполнения;
- название задачи;
- описание, если оно заполнено;
- время или дату создания;
- кнопку редактирования;
- кнопку удаления.

Выполненная задача должна:

- отмечаться галочкой;
- становиться визуально менее контрастной;
- отображаться с зачёркнутым названием;
- оставаться в списке, пока пользователь её не удалит.

### 5. Фильтрация задач

Добавить три фильтра:

- Все;
- Активные;
- Выполненные.

Активный фильтр должен визуально выделяться.

### 6. Пустое состояние

Если задач нет, показать понятное сообщение:

«На сегодня задач нет. Добавьте первую задачу, чтобы начать планирование.»

Если все задачи выполнены, показать сообщение:

«Все задачи выполнены. Отличный результат!»

## Модель данных

Каждая задача должна иметь следующую структуру:

```js
{
  id: "уникальный идентификатор",
  title: "Название задачи",
  description: "Описание задачи",
  completed: false,
  createdAt: "дата и время создания"
}
```

## Логика приложения

### Добавление задачи

1. Пользователь вводит название.
2. Нажимает кнопку «Добавить задачу».
3. Создаётся новая задача.
4. Задача появляется в списке.
5. Статистика обновляется автоматически.
6. Данные сохраняются в `localStorage`.

### Выполнение задачи

1. Пользователь нажимает чекбокс.
2. Статус задачи меняется на выполненный или активный.
3. Обновляются:
   - количество выполненных задач;
   - количество оставшихся задач;
   - процент прогресса;
   - progress bar.
4. Изменения сохраняются в `localStorage`.

### Редактирование задачи

Пользователь может изменить название и описание уже созданной задачи.

После сохранения список и статистика должны обновиться.

### Удаление задачи

После нажатия на кнопку удаления задача удаляется из списка и из `localStorage`.

Перед удалением желательно показать подтверждение или использовать кнопку с понятным действием.

## Дизайн

Стиль:

- современный;
- минималистичный;
- светлый;
- спокойный;
- без перегруженности.

Рекомендации:

- белый или очень светлый фон;
- одна акцентная цветовая гамма;
- отдельный цвет для выполненных задач;
- скруглённые карточки;
- мягкие тени;
- удобные кнопки;
- хорошая читаемость текста;
- единые отступы между блоками.

Интерфейс должен выглядеть аккуратно и на компьютере, и на мобильном телефоне.

## Адаптивность

На мобильном экране:

- карточки статистики располагаются в одну или две колонки;
- форма добавления задачи перестраивается вертикально;
- кнопки остаются удобными для нажатия;
- текст не выходит за пределы экрана;
- список задач занимает всю доступную ширину.

## Технические требования

- Использовать React и Vite либо другой простой современный frontend-стек.
- Не использовать сервер и базу данных для первой версии.
- Использовать `localStorage`.
- Разделить приложение на понятные компоненты.
- Не хранить логику всей страницы в одном большом файле.
- Добавить базовую обработку ошибок.
- Не использовать сложные библиотеки без необходимости.
- Код должен быть понятным для дальнейшего редактирования.

## Критерии готовности

MVP считается готовым, если:

- приложение запускается без ошибок;
- пользователь может добавить задачу;
- пустая задача не добавляется;
- задачу можно отметить выполненной;
- выполненную задачу можно вернуть в активное состояние;
- задачу можно редактировать;
- задачу можно удалить;
- работают фильтры;
- статистика считается правильно;
- progress bar отображает реальный процент выполнения;
- задачи сохраняются после обновления страницы;
- пустое состояние отображается корректно;
- приложение удобно работает на мобильном экране;
- в консоли браузера нет критических ошибок.

## Тестовые сценарии

Проверить:

1. Открыть приложение без задач.
2. Добавить одну задачу.
3. Добавить несколько задач.
4. Попробовать добавить задачу без названия.
5. Отметить одну задачу выполненной.
6. Проверить пересчёт статистики.
7. Переключить фильтр «Активные».
8. Переключить фильтр «Выполненные».
9. Отредактировать задачу.
10. Удалить задачу.
11. Обновить страницу и проверить сохранение данных.
12. Проверить приложение на мобильной ширине экрана.
13. Отметить все задачи выполненными.
14. Проверить сообщение о завершении всех задач.
